# Проект и назначение

> Родительский индекс: [`HANDOFF.md`](../../HANDOFF.md)

## Назначение

**AI Usage for GNOME** — пользовательский индикатор для верхней панели GNOME, который сводит в одном меню состояние AI-подписок и API-баланса:

- Claude Code: название профиля, заданный пользователем тариф, модель, остаток 5-часового и недельного окна;
- Codex: название профиля, email, тип тарифа, остаток короткого и недельного окна;
- DeepSeek API: доступность API и баланс по возвращаемым валютам;
- несколько независимых аккаунтов каждого поддерживаемого провайдера.

Основная целевая среда — GNOME на Bluefin/Bluefin DX. Установка должна быть простой, пользовательской и полностью обратимой.

## Проблема

При одновременной работе с несколькими Claude/Codex аккаунтами пользователь вынужден:

1. открывать отдельные приложения или CLI-сессии;
2. помнить, какой аккаунт сейчас авторизован;
3. вручную проверять 5-часовые и недельные лимиты;
4. переключаться между профилями, чтобы понять, где остался доступный лимит;
5. отдельно проверять баланс API-провайдера.

Это создаёт лишние переключения контекста и риск начать задачу на почти исчерпанном аккаунте. Виджет должен дать ответ за один клик, не становясь ещё одним тяжёлым приложением.

## Основные пользовательские сценарии MVP

### Быстрая проверка

Пользователь видит в панели минимальный оставшийся процент среди доступных лимитов, открывает меню и сравнивает аккаунты.

### Несколько профилей

Пользователь добавляет, например, один Claude и два Codex профиля. Каждый профиль имеет стабильный ID, отображаемое имя и отдельный каталог авторизации.

### Простая настройка

Команда `ai-usage setup` проводит через интерактивный мастер. Ручное редактирование TOML остаётся запасным способом, а не обязательным шагом.

### Безопасное удаление

Команда `ai-usage-uninstall` отключает user-service и расширение, удаляет пользовательские файлы и восстанавливает Claude `statusLine`, который существовал до установки hook.

### Автоматический релиз

Тег `v*` должен собрать архивы для `x86_64` и `aarch64`, вычислить SHA-256 и создать GitHub Release.

## Функциональный scope MVP

В MVP входят:

- GNOME panel indicator и popup menu;
- локальный Rust daemon;
- TOML-конфигурация с произвольным количеством аккаунтов;
- Claude Code status-line cache;
- Codex App Server JSON-RPC integration;
- DeepSeek balance endpoint;
- `setup`, `doctor`, `once`, `daemon`, `init`;
- пользовательская установка/удаление;
- systemd user-service;
- CI и release workflow.

## Нефункциональные требования

- **Низкий риск для GNOME Shell:** UI читает локальный файл, сеть находится вне shell-процесса.
- **Rootless:** никакого `sudo`, `/usr`, system-wide extension или system service.
- **Изоляция аккаунтов:** отдельные config/home каталоги.
- **Отказоустойчивость:** ошибка одного аккаунта представляется как `AccountState::error`, остальные продолжают отображаться.
- **Приватность:** нет телеметрии, внешнего backend и синхронизации; секреты не входят в state.
- **Обратимость:** удаление не должно уничтожать пользовательские настройки Claude.
- **Небольшое число зависимостей:** один Rust-бинарник плюс GNOME extension.

## Критерий готовности MVP

MVP можно считать готовым к первому публичному релизу только когда одновременно выполнено следующее:

- Rust проект компилируется на CI без предупреждений, тесты проходят;
- release bundle устанавливается на чистый пользовательский профиль Bluefin;
- расширение реально запускается на целевой GNOME Shell;
- один Claude, два Codex и опциональный DeepSeek показывают корректные данные;
- отказ/неавторизованность каждого провайдера отображается без падения daemon;
- uninstall восстанавливает Claude settings и не оставляет активный service/extension;
- online installer проверяет скачанный артефакт либо риск явно принят для `v0.1.0`.

Текущее соответствие этим критериям описано в [`STATUS.md`](STATUS.md).
