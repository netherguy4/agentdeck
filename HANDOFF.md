Этот файл — короткая точка входа для разработчика или следующей модели. Не загружай всю документацию сразу: открой только файл, связанный с текущей задачей.

## Что это за проект

AI Usage for GNOME показывает в верхней панели GNOME состояние нескольких аккаунтов Claude Code, Codex и, опционально, баланс DeepSeek API. Проект решает проблему отсутствия единого быстрого представления подписочных лимитов при работе с несколькими AI-аккаунтами.

Архитектура гибридная: GNOME Shell extension на GJS отвечает только за UI, Rust-процесс собирает данные провайдеров и атомарно записывает локальный `state.json`.

## Состояние одним абзацем

Основные компоненты MVP написаны: Rust CLI/daemon, три provider-адаптера, multi-account конфиг, Claude status-line hook, GNOME-индикатор, rootless install/uninstall, systemd user-service и GitHub Actions. Статическая проверка скриптов, JavaScript, JSON/TOML/YAML, упаковки и изолированной установки/удаления пройдена. **Rust-код в текущей среде не компилировался, реальные Claude/Codex/DeepSeek аккаунты и GNOME Shell не проверялись.** До первого публичного релиза MVP нельзя считать production-ready.

## Рекомендуемый следующий шаг

1. Добавить и закоммитить `Cargo.lock`.
2. Запустить `cargo fmt --all -- --check`, `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings` и release build.
3. Исправить найденные ошибки компиляции.
4. Протестировать сначала один Codex-аккаунт, затем два независимых `CODEX_HOME`.
5. Протестировать Claude hook с существующим пользовательским `statusLine` и последующее восстановление.
6. Протестировать расширение на фактической версии GNOME в Bluefin.
7. Только после этого создавать тег `v0.1.0`.

Подробная матрица — в [`TESTING.md`](docs/handoff/TESTING.md).

## Инварианты, которые нельзя случайно сломать

- Установка и удаление должны работать **без `sudo`** и не менять системные файлы.
- Несколько аккаунтов должны быть изолированы через отдельные `CLAUDE_CONFIG_DIR` / `CODEX_HOME`.
- GNOME extension не должен выполнять сетевые запросы и не должен блокировать GNOME Shell.
- Сбой одного провайдера не должен скрывать данные остальных аккаунтов.
- API-ключи и auth-файлы нельзя выводить в `state.json`, логи или интерфейс.
- Удаление должно безопасно восстановить прежний Claude `statusLine`, не перезаписывая более новые пользовательские изменения.
- Изменения формата `state.json` требуют увеличения `schema_version` и обратной совместимости UI либо явной миграции.

## Как поддерживать handoff актуальным

После существенного изменения обнови минимум:

- дату и краткий статус в этом файле;
- соответствующий раздел в [`STATUS.md`](docs/handoff/STATUS.md);
- тестовое доказательство в [`TESTING.md`](docs/handoff/TESTING.md);
- [`ROADMAP.md`](docs/handoff/ROADMAP.md), если изменился scope или приоритет.

Не отмечай интеграцию «готовой» только потому, что код существует. Для статуса «проверено» укажи среду, команду или сценарий, который реально прошёл.
